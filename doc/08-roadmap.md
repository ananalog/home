# 08. Этапы работ и открытые вопросы

## Этапы

Порядок выбран так, чтобы как можно раньше получить работающую цепочку «датчик → сервер → телефон»,
а сложные вещи (безопасность, BLE-приложение) наращивать на рабочем фундаменте.

| # | Этап | Результат |
|---|---|---|
| 0 | **Протокол** | `schema.yaml`, генератор (Go + C), тест-векторы; эмулятор устройства на Go |
| 1 | **Сервер MVP + CLI** | gateway (пока без шифрования, флаг `insecure`), реестр, SQLite, `homectl devices/get/set/watch`; работает с эмулятором |
| 2 | **Прошивка MVP CO2** | `home_core`: Wi-Fi (настройки через menuconfig), mDNS, TCP-сессия, точки; драйвер ACD1200, экран. Реальный датчик виден в CLI |
| 3 | **Mini App MVP** | авторизация initData, Дом/Устройство/график, Cloudflare Tunnel, бот с кнопкой; скрипты bootstrap/deploy |
| 4 | **OTA** | OTA в протоколе, раздел factory, откат, дескриптор образа; `homectl fw …` и экран «Прошивки» в Mini App; `fw-build/flash/publish` |
| 5 | **BLE + Android MVP** | GATT-сервис в ядре, PIN на экране; приложение: поиск, Wi-Fi, DHCP/статика, сервер, сбросы, логи |
| 6 | **Безопасность** | Noise XX, принятие устройств с кодом, роли пользователей, аудит |
| 7 | **Полировка** | уведомления/пороги, OTA по BLE из Android, канареечная раскатка, бэкапы наружу, core dump |
| 8 | **Дальше** | автоматизации (CO2 > 1000 → включить вентиляцию), новые устройства (реле, климат), мост в Home Assistant/MQTT по желанию |

Шифрование вынесено на этап 6 только ради скорости первых итераций: формат фрейма с первого дня
предусматривает место под AEAD-тег, поэтому включение не ломает протокол. Если сеть не доверенная
(гостевой Wi-Fi, соседи), этап 6 стоит поднять сразу после 2.

## Открытые вопросы

1. **Плата «Egg»:** объём flash, модель/разрешение OLED и его пины, есть ли светодиод/кнопки кроме BOOT,
   выведен ли 5 В. Лучше всего — ссылка на товар или фото платы с обеих сторон.
2. **ACD1200:** уровни I2C (есть ли подтяжка к 5 В), напряжение питания и ток — по даташиту конкретной модели.
   Будет ли использоваться I2C или UART?
3. **Сервер:** на каком железе (x86 мини-ПК / Raspberry Pi)? Какой дистрибутив?
4. **Доступ извне:** есть ли домен? Устраивает ли Cloudflare Tunnel, или Mini App нужен только дома?
5. **Пользователи:** сколько человек будет пользоваться, нужны ли разные роли?
6. **Репозитории:** создать ли `home-protocol`, `home-firmware`, `home-android` рядом с `ananalog/home`
   (или оставить протокол внутри `home/protocol/` на старте)?
7. **Сеть устройств:** отдельный VLAN/SSID для IoT есть? От этого зависит, насколько срочно шифрование (этап 6).
8. **Заводские данные:** нужны ли наклейки/QR с PIN для будущих устройств без экрана?
