# 04. Android-приложение

Назначение: настройка устройств **по Bluetooth в любой момент**, независимо от того,
есть ли у устройства связь с сервером. Сервер приложению не нужен (но может использоваться, если доступен).

## Стек

- Kotlin, Jetpack Compose, Material 3, minSdk 26 (Android 8), targetSdk — актуальный.
- BLE: собственный слой поверх `BluetoothGatt` (очередь операций, MTU 247, уведомления) и `BluetoothLeScanner`
  с фильтром по UUID сервиса.
- Протокол: сгенерированные Kotlin-кодеки из `home-protocol` (git submodule / composite build).
- Coroutines + Flow, ViewModel; логика протокола — в чистом Kotlin-модуле `core` (тесты на эмуляторе устройства).

## Разрешения

Android 12+: `BLUETOOTH_SCAN` (с `neverForLocation`), `BLUETOOTH_CONNECT`.
Android 8–11: `ACCESS_FINE_LOCATION` для сканирования.

## Экраны

1. **Поиск** — список устройств поблизости (фильтр по UUID сервиса): имя, модель,
   RSSI, значок «не настроено». Сортировка по силе сигнала — ближайшее сверху.
2. **Подключение** — устройство с экраном показывает 4-значный код, пользователь вводит его в приложении
   (`PAIR_CODE`); устройство без экрана — «нажмите кнопку на устройстве» (5-минутное окно).
   Шифрования BLE нет (решение владельца), код защищает только от случайных соседей.
3. **Устройство (обзор)** — модель, `device_id`, версия прошивки, активный раздел
   (`factory`/`ota_0`/`ota_1`), состояние Wi-Fi и связи с сервером, текущие значения точек.
4. **Wi-Fi** — кнопка «Сканировать» (сканирует **устройство**: видно то, что видит оно,
   с его RSSI), выбор сети, пароль, скрытая сеть вручную. После применения — живой статус
   подключения (`connecting → got IP 192.168.1.57 → server connected`), ошибки понятным текстом
   (неверный пароль, нет DHCP, сервер не найден).
5. **IP** — переключатель DHCP / Статический; поля IP, маска (или /префикс), шлюз, DNS;
   валидация (IP в подсети шлюза и т.п.); hostname.
6. **Сервер** — «Автоматически (mDNS)» или адрес:порт; если телефон в той же сети —
   кнопка «Найти сервер» (mDNS на телефоне) — адрес подставится сам.
7. **Устройство** — имя, комната (подсказка для сервера), режим BLE (`always/button/off`),
   настройки точек `setting` (например интервал измерений, калибровка CO2).
8. **Обслуживание**:
   - перезагрузка, «Идентифицировать» (мигнуть/показать на экране);
   - **сброс настроек** (Wi-Fi, IP, сервер, имя; прошивка остаётся);
   - **откат к заводской прошивке** (загрузка из `factory`-раздела);
   - **полный сброс** (оба);
   - все опасные действия — с подтверждением и вводом названия устройства;
   - просмотр логов устройства в реальном времени (сообщения `LOG`), экспорт в файл.
9. **Прошивка по BLE** — выбрать `.bin` из файлов телефона (или скачать с сервера/GitHub Releases),
   приложение проверяет дескриптор образа (модель совпадает), показывает прогресс,
   умеет продолжить после обрыва. Полезно, когда Wi-Fi недоступен или прошивка «не видит» сеть.

## Мастер первичной настройки

Для нового устройства экраны 4→5→6→7 проходятся мастером, в конце —
«Готово: устройство подключено к серверу. Примите его в Telegram».

## Архитектура кода

```
app/
  ui/            экраны Compose, навигация
  device/        DeviceSession: BLE-соединение, фрагментация, запросы с req_id, таймауты
  proto/         сгенерированные кодеки (из home-protocol)
  ota/           загрузка образа, окно чанков, возобновление
  data/          история устройств, настройки
```

`DeviceSession` предоставляет suspend-API: `describe()`, `wifiScan()`, `setConfig()`,
`factoryReset(mode)`, `otaUpload(file): Flow<Progress>`, `values(): Flow<Report>`.

## Тестирование

- Юнит-тесты кодеков на тестовых векторах из `home-protocol`.
- Фейковый транспорт для `DeviceSession` (петля на эмулятор протокола).
- Ручное тестирование на реальном ESP32-C3; для CI — сборка и юнит-тесты.

## Дистрибуция

APK из GitHub Releases (sideload), подпись ключом из секрета CI. Google Play — опционально позже.
